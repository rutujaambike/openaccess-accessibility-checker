# Hacktoberfest issue catalogue

The 12 issue templates in `.github/ISSUE_TEMPLATE/` correspond to every item in the project brief. GitHub issue templates help students create issues; **they do not publish issues automatically**. Maintainers should create each GitHub issue from the corresponding template, assign an owner, and apply matching labels (`easy`, `medium`, `hard`, `good-first-issue`, and issue type).

**Already in the starter:** JSON export, CSV export, browser-only scan history, basic test suite, and actionable error messages. Their issue templates ask contributors to extend or harden them. The color contrast checker, expanded headings, browser keyboard checks, ARIA validator, report filters, history comparison, PDF report, and extension are open contribution work. Do not describe an unimplemented issue as a working feature.

Suggested order: easy UI/docs/test issues → deeper rule checks → browser engine and PDF → extension. Run a two-person dry run before October and check that one can pick, build, test, and submit an issue without help.
